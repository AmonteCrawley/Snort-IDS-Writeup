# Snort-IDS-Writeup

They say teaching is the best way to memorize and truly understand what you have learned. So today, I want to share what I learned about Snort while completing a TryHackMe course. Don’t worry I will keep it short and to the point. Snort is an Intrusion Detection System (IDS). While a firewall is important for protecting the network from incoming and outgoing traffic, you can think of it as the bouncer at the door. Sometimes bad actors still get in, which is why Snort is important, it helps us recognize those bad eggs by detecting signatures, anomalies, and abnormal traffic patterns. Snort can also be used as a packet sniffer to display packets as they arrive on the network. For example, if I were to run an nmap scan on the network from another machine, Snort in sniffer mode would show the tcp packets in real time. Snort primarily operates as a Network Intrusion Detection System (NIDS). Unlike a Host Intrusion Detection System (HIDS), which monitors individual devices, NIDS monitors the entire network. This is something that is vital for organizations. While creating a rule in Snort, I noticed how similar the process is to creating a firewall rule. Even though they serve different purposes, they share similar components such as destination ports, protocols, and source/destination IP addresses. To create a Snort rule, you must follow a specific structure: Action, Protocol, Source IP, Source Port, Destination IP, Destination Port, and Rule Metadata. The metadata includes the message (msg), Signature ID (sid), and rule revision (rev). Example Rule: alert icmp any any -> 192.168.1.10 any (msg:"Ping Detected"; sid:10003; rev:1;) Writing rules was surprisingly easy to get the hang of, and I plan to continue learning more about rule creation and how to effectively use the Snort tool.
